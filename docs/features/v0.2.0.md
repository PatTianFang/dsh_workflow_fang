# v0.2.0 — DSH 0.2.1-rc.3 port

Released: 2026-10-28
Host baseline: DSH `0.2.1-rc.3` (`@deepseek-ai/dsh-*`), Cordis `4.0.5`, Schemastery `3.18.5`

## Goal

Keep every shipped workflow capability while moving the plugin onto the DSH
capability generation that shipped after `0.0.1-rc.2`. No user-visible feature
is removed; each host seam is re-expressed against the current API.

## Behavioral contract (unchanged)

- `dsh.workflow` v1 capsules, catalog discovery, save/rename/revise/delete.
- `async function run(wf, args)` with phase, spawn/run/wait/snapshot/output,
  send/stop, parallel, pipeline, synthesis, one-level nesting, artifacts, logs
  and token budget.
- Durable run graph, effect cache, rerun/resume-run, retention/prune.
- Read-only task policy, verification evidence, structured-output repair.
- Three tools (`workflow_list`, `run_workflow`, `workflow_manage`), the
  `/workflow` command family, one system-prompt section, background jobs and
  native `tool-workflow/*` Session events.

## Host seams that changed

| Seam | Old | New | Why |
| --- | --- | --- | --- |
| Child start | `ctx.subagents.start(provider, request)` | `ctx.subagents.startActivation({ provider, label, request, signal, delivery: 'caller' })` | The one-shot start API is gone; activations own cancellation and delivery policy. |
| Child handle | `SubagentRun.localAgent` | `parent.ctx.agents.get(childId)` | `SubagentRun` now carries only `{ id, result, dispose }`; live Agent resolution moved to the registry. |
| Read-only mask | `request.toolFilter` + `capabilities.toolFilter` | `child.ctx.tools.restrict(mask)` on the published child scope | DSH removed the per-delegation filter and points deployments at presets; the registry still owns per-scope restrictions, so the engine applies the same mask the seam used to apply. |
| History read | `session.events` | `session.ownEvents()` | Synchronous full-log reads were retired. |
| Tool evidence | `tool/result` content blocks | `tool/result` `message.toolCallId` / `message.isError` | The event now carries the identified `ToolResultMessage`. |
| Plugin message | `{ kind: 'plugin', plugin }` | registered `{ kind: 'dsh-workflow', form }` | The generic plugin wrapper is retired; producers register a durable kind through `MessageSourceMap`. |
| Background job | `owner: Agent`, `done.output` | `owner: agent.session.id`, `done.result` | Jobs are session-fenced and settle as `JobOutcome`. |
| Native run start | `{ runId, name, turn: null }` | `{ runId, name }` | The projection owns conversation scope; the caller coordinate was removed. |

## Fail-loud boundaries (unchanged philosophy, new mechanism)

- A read-only task whose provider publishes no local child Agent is rejected
  instead of running unconstrained.
- The structured-output repair child is denied every inherited tool (`allow: []`
  becomes a deny of the visible set), so reformatting cannot investigate.
- `target`/`effort` dispatch and worktree isolation still require deployment
  adapters and still fail loud when absent.

## Verification

- `npm run check`: compatibility pin, native projection contract, 179 tests,
  test typecheck, build.
- Live profile smoke: the installed bundle registers `workflow_list`,
  `run_workflow`, `workflow_manage` and completes an inline capability workflow
  (`install-smoke`) with the QuickJS VM, phase events and the run store.
